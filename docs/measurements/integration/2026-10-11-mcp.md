# Outside agents over MCP: hand-back report (feat/mcp)

Written 2026-10-10 by the builder session of `docs/plans/extensions/mcp.md`. The switch `features.mcp` is
**off** in this branch. Nothing was deployed.

## What was built

An agent that runs outside Premise (Claude Code, Codex, any MCP client) joins a pool as one more attempt.

- **Specification first:** `docs/spec/07-mcp.md` (rules MC1 to MC25, three text blocks, Appendix A),
  committed before the code. Amendments, each marked "added 2026-10-10": FJ1 gains `mcp` (`01-core.md`);
  the card tag `attempt.tag.mcp`, About box 3 and the limits list lines 9, 15 and 16 (`03-floor.md`).
- **Token route** `POST /api/pools/{pool}/mcp-tokens` (owner). The token is `pmcp1_<body>.<hmac>`, signed
  with `OWNER_KEY`, for one pool, valid 4 hours. Nothing is stored; rotating the owner key revokes every token.
- **MCP endpoint** `POST /mcp/{pool}`: Streamable HTTP answered with plain JSON (no event stream). Methods
  `initialize`, `ping`, `tools/list`, `tools/call`; notifications answer 202; `GET`/`DELETE` answer 405.
  The session id is signed too, so the Worker keeps no state; the attempt id is derived from it.
- **Nine tools:** `premise_start`, `premise_status`, then the seven tools of `05-agent.md` 3.1 with the same
  names, descriptions and argument schemas.
- **The outside attempt** is the attempt's own Agent Durable Object with a new `outside` driver. Each call
  goes through the model path's own code: TD3 normalization, TD4 to TD6 refusals (the guide first, the
  statement after a repair), the journal of AG1, Trunk's retries, the tool row, `attempt.step` events. The
  client receives the same `ModelToolMessage` a Premise model reads, heads-ups first.
- **Model gate:** a new `claim` call takes an agent slot with no model call and no money (`src/core/gate`).
- **Redaction:** `redact()` removes MCP tokens (family `mcp_token`); the request text is redacted before it
  becomes the intent's text.
- **Floor:** the card shows the client's name as the model and the tag "Over MCP".

## Choices made where the specification was silent

1. **Attempt kind `real`, model `mcp/<client name>`.** The Floor, Trunk and the note need no new kind; the card
   shows the client's name through the existing model short name. Clef triage applies as to any model.
2. **Silence is 2 minutes (`MCP_SILENCE_MS`), not `AGENT_WATCHDOG_MS` (30 s) as the plan said.** Claude Code
   asks its user to approve the first call of each MCP tool, and a large model can take over 30 s to write one
   file. With 30 s the lead's live check would likely stop the attempt while the owner reads a permission
   prompt. To follow the plan exactly, change one constant in `src/worker/mcp/constants.ts` and Appendix A.
3. **The slot is released while the change is handed in** (validated, held, accepted), as MG5 does for
   Premise's agents, and claimed again if a heads-up sends it back to work.
4. **Heads-ups:** in the next tool result (as for Premise's agents) or `premise_status`; `premise_status` with
   `wait: true` waits up to 20 s. The plain-JSON transport has no server push.
5. **An outside attempt is never resumed:** its model is not in the model plan, so RS3 already answers
   `model_unavailable`. "Try again" or an undo reopen ends as `reopen_failed`.
6. **Kill switch fails closed:** if the gate cannot be asked, the MCP route answers 503.
7. **Parallel calls:** a client that calls tools in parallel gets TL8's `not_run` after a failure, a heads-up
   or a submit in the same turn, so no call is sent with an `ack` the client's model has not read.
8. **Routes outside 13.6's table:** the two routes live in a new `MCP_ROUTES` table in
   `src/protocol/routes.ts` (the 13.6 table's own test counts 21 rows), and `src/worker/index.ts` matches it.
