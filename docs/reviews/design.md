## Findings

Each finding: severity, rule, screenshots, what is wrong, suggested fix. Code references are to the

### D1 — high — 6.3, VD9, AX1 (AC9) — card sheets unreadable in the light theme

Screens: `sizes-beat03-held-sheet_stage_light_owner.png`, `sizes-beat03-held-sheet_laptop_light_owner.png`,
`sizes-beat04-race-sheet_stage_light_three-ready.png`, `sizes-beat04-race-sheet_laptop_light_three-ready.png`.

`card-sheet.css` uses `--bg0` and `--bg1` (lines 6, 17, 243), which no theme defines, so the sheet keeps
its dark fallback `#12222e` in both themes. In the light theme the text token is `#0e1d26`: the title, the
model names, "Who it affects", the checks and the path are at 1.06:1, muted text at 2.25:1. Beats 3 and 4
in a bright room cannot be read. The token test of AC9 passes because it never sees the undefined
tokens. Fix: build the card sheet from the page tokens (`--surface`, `--bg`) like `.sheet` in `base.css`.

### D2 — high — LY4, 2.4 — the card sheet covers the header, the strip and the banners

Screens: `sizes-beat03-held-sheet_stage_dark_owner.png`, `sizes-beat03-held-sheet_laptop_dark_owner.png`,
`labels-held-sheet_stage_dark_replay-synthetic.png`. Data: `sizes-measure_{stage,laptop}_held-sheet.json`.

The card sheet's backdrop is `position: fixed; inset: 0; z-index: 40` (`card-sheet.css:3-10`), outside
`.floor-main`. It dims the whole page; a tap at the kill switch or at a strip cell lands on the backdrop
(`onTop`). At stage the sheet's top edge (y 112) overlaps the strip; at laptop the sheet title sits on the
strip; in Replay it hides most of the SYNTHETIC and REPLAY sentences. Fix: render the card sheet in
`.floor-main` like the other sheets, so it starts under the banners.

### D3 — high — 2.5, 2.8, CO23b — Why, git drawer and Who relies are centred over the pool

Screens: `sizes-beat06-why_stage_dark_crab.png`, `sizes-beat06-why_laptop_light_crab.png`,
`sizes-beat06-git_stage_dark_crab.png`, `sizes-beat02-who_stage_dark_energy-max.png`,
`sizes-beat02-who_laptop_dark_energy-max.png`. Data: `sizes-measure_*_why.json`, `sizes-measure_*_who.json`.

`why.css` and `who-relies.css` give the sheets 760 px at the right edge, but `base.css`'s `.sheet` and
`.sheet-backdrop` have the same specificity and come later in the built CSS (in
`dist/client/assets/index-*.css`, `.why-sheet` at byte 13,875, `.sheet` at 29,568), so they win: the
sheets are 720 wide and centred, the git drawer docks at the far left, and the 70% backdrop dims the
pool. Beat 6 ("the tapped creature stays in view") and beat 2 ("the same creatures are outlined in the
pool", "the same attempt cards and lights are outlined in the rail") lose their picture. The undo sheet is
720 instead of 560 for the same reason. Fix: give the sheet rules higher specificity (for example
`.sheet.why-sheet`) or load `base.css` first, and leave the pool area clear behind the Why and Who
sheets.

### D4 — high — VD15, 6.2 — voiceover text under 22 px at stage size

### D5 — high — RY23 — the owner gets the visitor's start card

Screens: `sizes-beat01-floor_stage_dark_owner-before-start.png`, `sizes-beat01-floor_stage_light_owner-before-start.png`;

### D6 — high — CO8, FL10, 3.1 — the intent box waits for an event that has arrived

Screens: `copy-intent-box_stage_dark_sent-waiting-6s.png`, `keyboard-beat01-box-after-starter_stage_dark_6s.png`.
Data: `copy-intent-box-after-send.json`, `box-1s-after-intents` and `box-6s-after-intents` in `keyboard-beats.json`.

The effect that clears the draft depends on `[floor.intents, draft, phase]` (`intent-box.tsx:66-79`), but
the reducer changes `FloorState` in place (`session.ts:193`), so the arrival of `intent.created` never
re-runs it. When the event reaches the socket after the create request has answered (300 ms later in the
capture), the request stays in the field, the field is read-only with "Sending…" for `SENT_WAIT_MS`, and
then "Sent. Waiting for the pool to show it." appears with Send and Race 3 off, until the owner edits the
text. After "Send the starter set" the keys-only run shows the same: 1 s after the six intents arrived the
box read "Sending…" with the field read-only, and 6 s after, "Sent. Waiting for the pool to show it."
with Send and Race 3 off. In runs that were not kept, with the events 0, 200 and 3,000 ms after the
replies, the field stayed read-only with "Sending…" for about 5 seconds each time, and at 200 and 3,000 ms
the false wait sentence followed. So the owner cannot type the crab request for 5 seconds, and may then
read a false wait sentence (beat 1). Fix: re-check the awaited
intent ids on every applied event (for example depend on `floor.n`).

### D7 — high — 3.15, CO42, CO44a, FR24, FL10 — Swarm view reads the wrong pool

Screens: `sizes-beat08-swarm_stage_dark_main-pool-stream.png`, `sizes-beat08-swarm_laptop_light_main-pool-stream.png`,
`known-c-swarm-start_stage_dark_3-running-no-attempt.png`, `known-c-swarm-start_stage_dark_4-after-10s.png`.
Data: `sockets` in `sizes-measure_stage_swarm.json`, `known-c-swarm-start.json`.

Swarm view draws the main pool's `FloorState` (`app.tsx:603-604`); the page opens one socket,
`/api/pools/tidepool/stream`, and none for `tidepool-swarm`. In a live run the scripted attempts and the
`metrics` are on the Swarm pool's stream, so the wall stays empty, the four numbers are the main pool's,
and "Starting n scripted agents…" stays on screen. FR24 asks for `swarm.no_agents` after 10 s without a
synthetic attempt; after 11 s the page still read "Starting 64 scripted agents…" (there is no such
timer). This is a data-source fault seen through the page; beat 8 depends on it. Fix: open the stream of
`settings.swarm_pool` for Swarm view, and add the 10-second `swarm.no_agents` check.

### D8 — high — CO41, VD2, FL5 — the Swarm wall is a grid of text tiles

Screens: `sizes-beat08-swarm_stage_dark_wall-256.png`, `labels-swarm-view_stage_dark_replay-synthetic.png`.
Data: `sizes-measure_stage_swarm-wall.json`.

1,024 would be about 3,600 px. Fix: draw the wall on one canvas with the CO41 shapes and a cell size
computed from the agent count.

### D9 — high — FL5, 5.10 (CD5), FL4, RY27 — the default recording
