# Clef, stage 1: the hand-back report (feat/clef)

Written 2026-10-10 by the Clef builder session. Stage 1 of `docs/plans/extensions/clef.md`.
`features.clef` stays false and the three switches stay `off`, so the shipped build behaves as
before, with one deliberate fix (the switch wiring, below). Stage 2 (`npm run calibrate:clef`) is
not built.

## What was built

1. **The question store (01-core TR10, new spec text).** A pending Clef question is written to a
   new table `triage_asks` in the accept transaction, with the S6 question and the frozen item that
   V7 needs. A reopened Trunk engine rebuilds the item from the row, so V7 re-rows a pending
   question on every operation whatever object instance serves it. Before, the Durable Object
   reopened the engine on every call while a triage was pending and lost the item, so V7 skipped
   it and a late answer for an old patch would have decided.
2. **Dispatch, deadline and restart (TR2, TR6, TR10).** Engine entries `triage_dispatch`,
   `triage_deadline` and `triage_restart`; a `triage` timer at the earliest deadline.
3. **`ClefTriage` and `ClefRisk`** (`src/worker/adapters/triage/`, `src/worker/adapters/risk/`)
   over the `AI` binding, through the model gate (TR9), with TR7's size and token checks, Trunk's
   own time-out, and every failure mapped to an unavailable answer with an error code.
4. **The runner** (`src/worker/trunk/triage-runner.ts`) and its wiring in the Trunk object: after
   each commit, off the request path, it sends the unsent questions and applies the answers.
5. **The switch.** The Trunk object now passes `CLEF_TRIAGE` and `CLEF_RISK` to the engine: `on`
   only when `features.clef` is true and the environment variable is `on`.
6. **The held card's risk lines (RK1, RK3, new RK5).** A full held card of a real attempt queues
   its submit when `CLEF_RISK` is on; the answers fill `Card.risk` with `card.updated`. The Floor
   already drew the lines; a browser test now proves them.
7. **Clef's price in the model plan** ($0.240 per million input tokens for `clef`, $0.038 for
   `clef-flash`, no output charge; Workers AI pricing page). Without it the gate refuses every
   Clef request with `spend_cap`.

## A live bug this fixes (high)

Before this branch the Trunk object passed no switch to the engine, and the engine's default is
`CLEF_TRIAGE = on`. So in the deployed build a **real** agent whose read file changed underneath it
(rows E3, F4, F6, QT2, QR4) got a pending triage that nothing would ever answer: the attempt could
not land (TR2) and stayed `submitted`. Synthetic agents were never affected (ScriptedTriage), which
is why the hero runs and the swarm did not show it. With this branch and the switch off, those
rows answer `confirm` with `triage_unavailable` inside the transaction (TR5), which is the
specified behaviour of a build without Clef. Evidence: `src/worker/trunk/trunk-do.ts` before the
change called the engine with `{ now, syncTriage, features }` only; `src/core/trunk/registry.ts`
sets `clefOn = (opts.switches?.CLEF_TRIAGE ?? "on") === "on"`.

## Choices made where the specification was silent

- Clef question ids must be letters, digits, `_`, `.` or `-` (Clef model page), so the premises
  travel as `p1`, `p2`, … and the answers map back to `<kind>:<key>`.
- The request's premise entry has the fields of 7.3's example (`kind`, `key`, `read_then`,
  `is_now`, `changed_by_intent`, and `added` when present). `rule` and `changed` stay in Trunk.
- `changed_by_intent` comes from the landing the judgment names (`cause_seq`) when the batch gave
  no cause attempt.
- An error code is recorded only on the answers it made unavailable. Codes: `timeout`,
  `rate_limited`, `spend_cap`, `killed`, `gate_unavailable`, `model_unavailable`,
  `model_rejected`, `malformed`, `state_too_large`, `truncated`, `too_many_questions`, `stale`.
- A late answer whose judgment is already closed records `stale` on that judgment, replacing an
  earlier code such as `timeout` (TR4's words).
- A held card of a synthetic attempt asks Clef nothing (TR8's rule extended to risk).
- A risk question an earlier object instance sent is unavailable (`timeout`), not asked again.
- V7's rule close now records the row's reason on the judgment (it kept the triage reason before).
